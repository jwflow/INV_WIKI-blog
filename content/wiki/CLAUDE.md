# wiki/ 운영 규칙

이 폴더는 **AI가 전적으로 작성·관리**하는 지식 기반이다. 사용자는 읽기만 한다.

## 하위 폴더 구조

| 폴더 | 내용 |
|---|---|
| market/ | 시장 국면, 매크로 분석, 금리·유동성 환경 |
| themes/ | 시대정신 테마별 페이지 (AI, 항공우주, 화폐시스템 개혁) |
| assets/ | 종목·자산별 페이지 (ETF, 개별주식, 암호화폐) |
| portfolio/ | 현재 포트폴리오 현황, 비중, 손익 |
| decisions/ | 매수·매도 의사결정록 |

## 핵심 파일

- `index.md` — 전체 페이지 목차. 질의 시 **가장 먼저 읽는다**.
- `log.md` — 활동 로그 (append-only). 모든 ingest·query·lint 후 반드시 추가.
- 루트 `AGENT_HANDOFF.md` — 에이전트 교체를 위한 최신 운영 상태. 미완료·오류·주의사항이 있으면 함께 갱신한다.

## 자산 페이지 업데이트 원칙 (선별 업데이트)

자산 wiki 페이지를 업데이트할 때는 **전체 갱신이 아닌 선별 업데이트**를 기본으로 한다.

### 업데이트 대상 (우선순위 순)

1. **Top 10 후보** — 현재 `output/top10/` 최신 파일에 포함된 종목은 항상 업데이트
2. **당일 급락(-10% 이상)** — 손절선 도달 또는 thesis 훼손 가능성 → 즉시 업데이트 + 경보 섹션 추가
3. **당일 급등(+7% 이상)** — 단기 과열 경고 또는 테마 재부각 확인 필요 시 업데이트
4. **이벤트 발생** — 수주 공시, 실적 발표, 규제 변화 등 thesis에 영향을 주는 뉴스

### 업데이트 제외 (노이즈 방지)

- Top 10 미포함 + 일간 ±3% 미만 + 특별 이벤트 없음 → **업데이트 생략**
- 모든 종목을 매일 업데이트하면 신호 대비 노이즈가 과다해진다

### 일일점검 커버리지 한계

`scripts/daily-assets.json`에 등록된 35개 자산만 가격이 자동 수집된다. 미등록 종목(나무기술, 라온텍, 케이엔솔, Circle 등)은 별도 조회 없이는 당일 가격 데이터가 없으므로 업데이트를 강제하지 않는다.

## 페이지 작성 원칙

1. 프론트매터 반드시 포함 (루트 CLAUDE.md 형식 참조)
2. 교차 참조는 `[[페이지명]]` 형식으로 링크
3. 새 페이지 생성 시 `index.md`에 즉시 추가
4. 기존 페이지 업데이트 시 `updated` 날짜 갱신
5. 소스 인용 시 `[[raw/폴더/파일명]]` 형식 사용

## 자산 페이지 필수 섹션

```
## 투자 thesis
## 비교우위 점수 (스코어카드)
## 상승 시나리오
## 하락 시나리오 / 리스크
## 기술적 위치
## 재평가 조건
## 관련 소스
```

## log.md 항목 형식

`## [YYYY-MM-DD] ingest | 제목`
`## [YYYY-MM-DD] query | 질문 요약`
`## [YYYY-MM-DD] lint | 점검 요약`
`## [YYYY-MM-DD] tooling | 자동화·스크립트·운영 변경`
`## [YYYY-MM-DD] handoff | 에이전트 인수인계 상태`

## 에이전트 인수인계 로그 규칙

작업자는 다음 에이전트가 같은 파일을 다시 분석하거나, 이미 무효 처리된 내용을 믿지 않도록 구체적으로 남긴다.

- 새 자산·테마·output 생성 시: 파일 경로, 점수/상태, 핵심 결론, 인덱스 반영 여부를 기록한다.
- 기존 파일 수정 시: 무엇을 왜 바꿨는지, 관련 링크/카운트 변경 여부를 기록한다.
- 미완료 작업이 있으면 `남은 작업/주의` 항목으로 명시한다.
- 오류가 있는 산출물은 삭제보다 `무효 처리` 또는 `주의` 표시를 우선하고, 로그와 `AGENT_HANDOFF.md`에 이유를 남긴다.
- 최종 답변 전에 `wiki/log.md`와 루트 `log.md`가 같은 사건을 가리키는지 확인한다.
